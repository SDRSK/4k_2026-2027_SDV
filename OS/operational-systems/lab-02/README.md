# Лабораторна робота №2

**Тема:** Системні виклики ядра Linux для роботи з файловими дескрипторами.

**Мета:** дослідити `open`, `read`, `write`, `close`, `lseek`, обробку помилок та копіювання файлів.

## Запуск (з каталогу lab-02)

```bash
gcc --version
gcc -Wall -Wextra -pedantic -o fd_demo fd_demo.c
./fd_demo

gcc -Wall -Wextra -pedantic -o copy_file copy_file.c
./copy_file notes.txt notes-copy.txt
cmp notes.txt notes-copy.txt
```

Результат `fd_demo`:

```text
Прочитано 18 байтів: Hello from lab-02
Зі зміщення 11 прочитано 6 байтів: lab-02
```

Якщо `cmp` нічого не виводить і має код повернення `0`, вміст файлів однаковий.

## Завдання 2: перевірка зміщення

Якщо змінити `lseek(fd, 11, SEEK_SET)` на `lseek(fd, 0, SEEK_SET)` і `read(fd, buffer, 6)` на `read(fd, buffer, 5)`, результат другого читання буде `Hello` (5 байтів). Після перевірки потрібно повернути вихідні значення. Основний `fd_demo.c` уже з відновленими значеннями.

Для трасування, якщо встановлено `strace`:

```bash
strace -e trace=openat,read,write,lseek,close ./fd_demo
```

У трасуванні знайдіть `openat` (відкриття файла; це типова реалізація `open` у Linux), `write` (запис), `read` (читання), `lseek` (встановлення позиції) і `close` (закриття). Можливі додаткові виклики завантажувача та бібліотек.

## Пояснення системних викликів

| Виклик | Аргументи | Успіх | Помилка |
|---|---|---|---|
| `open(path, flags, mode)` | шлях, прапорці, права при створенні | файловий дескриптор `>= 0` | `-1`, встановлено `errno` |
| `read(fd, buf, count)` | дескриптор, буфер, максимальна кількість байтів | кількість прочитаних байтів (`0` — кінець файла) | `-1`, `errno` |
| `write(fd, buf, count)` | дескриптор, буфер, кількість байтів | фактично записана кількість байтів (може бути меншою за `count`) | `-1`, `errno` |
| `lseek(fd, offset, whence)` | дескриптор, зміщення, початкова позиція | нова позиція у байтах | `(off_t)-1`, `errno` |
| `close(fd)` | дескриптор | `0` | `-1`, `errno` |

`O_WRONLY` відкриває для запису; `O_CREAT` створює файл, якщо його немає; `O_TRUNC` обрізає наявний файл до нуля; `0644` визначає права нового файла з урахуванням `umask`. `SEEK_SET` відлічує зміщення від початку файла. `lseek` не змінює вміст, лише позицію поточного читання/запису.

`copy_file` записує лише `n` байтів, тому що `read` може повернути менше за 4096; решта буфера не є частиною поточної порції даних. Наведена в умові версія спрощена: для промислової надійності слід повторювати `write`, поки не буде записано всі `n` байтів, і перевіряти помилки `close`.

## Відповіді на питання для захисту

1. **Файловий дескриптор** — невід’ємне ціле число, яким процес позначає відкритий файл або інший ввід/вивід. `open` при помилці повертає `-1`.
2. **`O_CREAT` та `O_TRUNC`:** перший створює файл за відсутності, другий очищає вже наявний файл під час відкриття для запису.
3. **`lseek`:** змінює поточне зміщення у відкритому файлі, не змінюючи самих даних.
4. **Чому `n`, а не 4096?** Бо `read` повертає фактично прочитану кількість байтів; запис усього буфера додав би зайві невизначені/старі байти.
5. **Чи можна лише бібліотекою?** Функції бібліотеки (`fopen`, `fread`, `fwrite`, `fclose` тощо) можуть надати інший інтерфейс, але для реальної роботи з файлами ОС зрештою використовуються системні виклики.
