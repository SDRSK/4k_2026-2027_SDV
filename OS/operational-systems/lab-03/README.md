# Лабораторна робота №3

**Тема:** Керування життєвим циклом процесів у C/Linux.

**Мета:** навчитися працювати з `fork()`, сімейством `exec`, `waitpid()` і макросами перевірки статусу процесу.

## Файли

- `process_demo.c` — один нащадок: `fork` → `execlp("echo", ...)` → `waitpid`.
- `worker_children.c` — три нащадки з нормальним і сигнальним завершенням.

## Компіляція та запуск

Перейдіть у папку `lab-03` у Linux або WSL:

```bash
gcc --version
gcc -Wall -Wextra -pedantic -o process_demo process_demo.c
./process_demo
gcc -Wall -Wextra -pedantic -o worker_children worker_children.c
ulimit -c 0  # необов'язково: не створювати core-файл після abort()
./worker_children
```

**Типовий вивід `process_demo`:**

```text
Батько: pid=1234, ppid=1000
Нащадок: pid=1235, ppid=1234
Нащадок запустив команду echo
Батько: нащадок завершився з кодом 0
```

Числа PID і PPID щоразу відрізняються.

**Вивід `worker_children`:**

```text
Нащадок 0: код завершення 10
Нащадок 1: сигнал 6
Нащадок 2: код завершення 12
```

`SIGABRT` зазвичай має номер 6 у Linux (на використаному середовищі саме 6).

## Завдання 2 — експерименти

Початковий файл `process_demo.c` залишено в оригінальному вигляді, щоб під час здачі він відповідав завданню.

### Варіант `ls -l`

У `process_demo.c` замініть:

```c
execlp("echo", "echo", "Нащадок запустив команду echo", (char *)NULL);
```

на:

```c
execlp("ls", "ls", "-l", (char *)NULL);
```

Знову виконайте:

```bash
gcc -Wall -Wextra -pedantic -o process_demo process_demo.c
./process_demo
```

**Результат:** між повідомленням нащадка й повідомленням батька з'явиться список файлів поточного каталогу з детальною інформацією. За успіху статус завершення — 0.

### Варіант із неіснуючою програмою

Замініть виклик `execlp` на:

```c
execlp("no-such-program-xyz", "no-such-program-xyz", (char *)NULL);
```

Повторіть компіляцію і запуск. Зазвичай `perror("execlp")` виведе:

```text
execlp: No such file or directory
```

Це означає, що `execlp` повернувся з помилкою: програми не існує. Нащадок виконує `_exit(127)`, а батько повідомляє код **127**. Число 127 задане нашим кодом, а не автоматично повернуте `execlp`.

Після експериментів поверніть початковий виклик `echo` перед завантаженням на GitHub.

## Пояснення ключових викликів

- **`fork()`** створює новий процес. У батьківському процесі повертає PID нащадка, у нащадку — `0`, у разі помилки — `-1`.
- **`execlp()`** знаходить програму через `PATH` і замінює поточний образ процесу на нову програму. При успіху не повертається; при помилці повертає `-1` і встановлює `errno`.
- **`waitpid(pid, &status, 0)`** очікує завершення конкретного процесу з PID `pid`, записує інформацію про стан у `status`. За успіху повертає PID процесу, за помилки — `-1`.
- **`WIFEXITED(status)`** істинний, якщо процес завершився звичайним способом (`return`, `exit`, `_exit`). **`WEXITSTATUS(status)`** отримує його код завершення (використовують, коли `WIFEXITED` істинний).
- **`WIFSIGNALED(status)`** істинний, якщо процес зупинився через необроблений сигнал; **`WTERMSIG(status)`** повертає номер сигналу.
- **`fflush(NULL)`** скидає буфери відкритих потоків stdio перед `fork`/`exec`, щоб раніше виведені повідомлення не дублювалися і не губилися при заміні образу процесу. `fflush` не гарантує повний порядок між незалежними процесами; порядок повідомлення батька після завершення забезпечує `waitpid`.

## Пояснення завдання 3

Батьківський процес створює три нащадки і зберігає їхні PID у масиві. Нащадок №0 виконує `_exit(10)`, №1 — `abort()` (надсилає процесу `SIGABRT`), №2 — `_exit(12)`. Батько викликає `waitpid(pids[i], ...)` послідовно для `i = 0, 1, 2`, тому **рядки звіту друкуються в порядку індексів**, навіть якщо реальний порядок завершення нащадків може відрізнятися.

## Питання для захисту

**1. Що повертає `fork` батьківському процесу, а що — нащадкові?**  Батькові — PID новоствореного нащадка (додатне число), нащадкові — `0`; за помилки — `-1` у процесі, який викликав `fork`.

**2. Чому після успішного `exec` подальший код не виконується?**  `exec` замінює образ поточного процесу іншою програмою; управління переходить до нової програми. Рядки після `execlp` виконуються лише за помилки.

**3. Що повертає `waitpid` і що містить `status`?**  За успіху — PID нащадка, стан якого отримано (зокрема, завершення), за помилки — `-1`. `status` — закодована інформація про те, як завершився процес (код виходу або сигнал); її аналізують макросами `WIFEXITED`, `WEXITSTATUS`, `WIFSIGNALED`, `WTERMSIG`.

**4. Чим відрізняється нормальне завершення від завершення сигналом?**  Нормальне — процес сам виконав `return`, `exit` або `_exit`, перевірка `WIFEXITED` і читання `WEXITSTATUS`. Сигнальне — процес завершено сигналом, перевірка `WIFSIGNALED` і читання `WTERMSIG`.
