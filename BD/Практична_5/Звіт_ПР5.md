# Практична робота №5. Первинне налаштування СКБД і створення навчальної бази

**Мета:** встановити PostgreSQL і графічний клієнт, створити роль, базу `college` з UTF8, схему `college` і підтвердити підключення трьома способами.

> **Статус виконання.** Підготовлено всі команди SQL і покрокові інструкції, але фактичне встановлення PostgreSQL, підключення до локального ПК та справжні скриншоти не виконувалися у цьому середовищі. Поля для версій та скриншотів треба заповнити за результатами запуску на власному комп'ютері. Фальшиві скриншоти та вигадані версії не додаються.

## 3. Інсталяція та запуск у Windows

1. Завантажте PostgreSQL з https://www.postgresql.org/download/windows/ і встановіть PostgreSQL Server, `psql` та за потреби pgAdmin. Встановіть власний пароль для ролі `postgres`.
2. Завантажте DBeaver Community з https://dbeaver.io/download/ та встановіть, якщо потрібні обидва графічні клієнти.
3. Перевірте, що служба PostgreSQL запущена у Windows Services. У PowerShell або SQL Shell (psql) перевірте `psql --version`. Якщо `psql` не в `PATH`, використайте SQL Shell (psql), встановлений разом із PostgreSQL.
4. Запустіть `psql -h localhost -p 5432 -U postgres -d postgres` і введіть пароль **інтерактивно**.
5. Виконайте `01_create_role_and_database.sql` через `\i 'ПОВНИЙ/ШЛЯХ/ДО/ФАЙЛУ/01_create_role_and_database.sql'` (у Windows можна використовувати прямі слеші). Перед цим **замініть** `REPLACE_WITH_OWN_PASSWORD` на власний пароль тільки у локальній копії файлу; не публікуйте цю копію.
6. Підключіться як `college_user`: `psql -h localhost -p 5432 -U college_user -d college`. У цій сесії виконайте `\i 'ПОВНИЙ/ШЛЯХ/ДО/ФАЙЛУ/02_create_schema_and_checks.sql'`.
7. Для перевірки через pgAdmin зареєструйте сервер `localhost:5432`, підключіться як `college_user` до бази `college`, відкрийте Query Tool і запустіть `03_verification_queries.sql`.
8. Для перевірки через DBeaver створіть підключення PostgreSQL (Host localhost, Port 5432, Database college, User college_user), відкрийте SQL Editor і виконайте `03_verification_queries.sql`.

**Увага:** У pgAdmin для підключення до вже створеної бази `college` виберіть Maintenance database `college` або відкрийте Query Tool саме на базі `college`. Якщо використовується інший користувач, `SELECT current_user` закономірно покаже його роль.

## 4. Очікувані команди та результати

```sql
SELECT version(); -- Реальна версія встановленого сервера PostgreSQL
SELECT current_database(); -- college
SELECT current_user; -- college_user, якщо ввійшли як навчальна роль
SELECT schema_name FROM information_schema.schemata ORDER BY schema_name;
-- У списку має бути college (а також системні схеми)
SELECT pg_encoding_to_char(encoding) AS encoding FROM pg_database WHERE datname='college';
-- UTF8
```

У PostgreSQL `CREATE DATABASE` не можна виконувати всередині транзакційного блоку; скрипт `01` слід запускати у звичайній psql-сесії, а не як одну транзакцію в деяких клієнтах.

## 6. Висновок

Розроблено відтворюваний порядок встановлення PostgreSQL і перевірки клієнтських підключень. Підготовлено сценарій створення ролі з правом `CREATEDB`, бази `college` у кодуванні UTF8 та схеми `college`. Запити перевіряють версію сервера, поточну базу, користувача, список схем і кодування. Фактичне підтвердження працездатності потребує виконання скриптів на встановленому сервері та додавання реальних скриншотів.

## Відповіді на питання для захисту

1. У PostgreSQL роль є універсальним об'єктом прав доступу; «користувач» — це роль із атрибутом `LOGIN`. Групові ролі можуть не мати LOGIN.
2. Схема — простір імен для таблиць, подань та інших об'єктів усередині однієї бази; допомагає розділяти модулі й права.
3. Командою `psql -h localhost -p 5432 -U college_user -d college` з інтерактивним введенням пароля.
4. Для українського тексту потрібне **UTF8**, яке підтримує кирилицю та інші символи Unicode.
